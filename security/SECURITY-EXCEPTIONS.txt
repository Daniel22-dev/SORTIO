EX-01 – INLINE CSP COMPATIBILITY
Finding/control: SH-APP-05 / CSP uses 'unsafe-inline' for script-src and style-src.
Severity: HARDENING / LOW-to-MEDIUM depending on future data flows; no confirmed exploitable HIGH/CRITICAL in tested release.
Scope: public and prepared school-server CSP.
Reason: current single-page architecture still contains required inline bootstrap/style behavior. Removing it is a separate modularization refactor and was not mixed into this security migration.
Impact: CSP is weaker than a nonce/hash-only policy.
Compensating controls: untrusted values are sanitized/escaped; hostile-render/XSS regressions; no unsafe-eval; frame guard; school profile adds server-delivered frame/security headers.
Owner role: application maintainer + school IT for served headers.
Target closure: future modularization/hardening release.
Closure condition: no executable inline code or a nonce/hash-based CSP verified behaviorally.

EX-02 – LOCAL STORAGE / SHARED DEVICE PRIVACY
Finding/control: privacy / SH-RUN-12.
Severity: PRIVACY / AMBER.
Scope: student/class data stored locally in teacher browser; exported backups.
Reason: local-first design.
Impact: another person with access to the same browser profile/device or exported file may access the data.
Compensating controls: clear/end-work flows, import validation, shared-device controls, no student data in diagnostic canaries, minimal logging.
Owner role: application maintainer + school operational policy.
Target closure: school-server/shared-device operational controls and/or stronger local isolation where practical.
Closure condition: validated shared-device lifecycle and server/session isolation with synthetic users.

Finding/control: RI-13 / SH-SC-10.
Severity: AMBER evidence gap, not an application vulnerability.

Closure condition: documented production key custody, backup, rotation, revoke and recovery drill.
