N-05  STŘEDNÍ – DEPLOY WORKFLOW SPADNE, NASAZENÍ NEPROBĚHNE
      Reprodukováno, nikoli odvozeno.

      .github/workflows/deploy.yml spouští pouze
        npm run build:deployment
      a nikde nestaví dist-school-server. Zkontroloval jsem to:
      ve všech pěti workflow není jediná zmínka o school profilu.

      O dva kroky později ale workflow volá
        node scripts/deployment-staging-regressions.mjs
      a tento skript iteruje přes OBA stagingy:
        const roots=['dist-deployment','dist-school-server'];
      Na druhém padne readFileSync na neexistujícím
      dist-school-server/index.html.

      Simuloval jsem přesnou posloupnost z CI v čistém stromu:
        npm run build:deployment      OK, vznikne dist a dist-deployment
        npm run garp25:leaks:public   PASS
        node scripts/deployment-staging-regressions.mjs
          FAIL dist-school-server:exists
          Error: ENOENT ... 'dist-school-server/index.html'
          EXIT 1

      Důsledek: krok "Deployment staging regression" selže, workflow
      skončí chybou a kroky Configure Pages / Upload / Deploy se
      nikdy neprovedou. Nasazení na GitHub Pages tedy vůbec
      neproběhne.

      Bezpečnostně to selhává bezpečným směrem – nic se nepublikuje.
      Prakticky to ale blokuje přesně ten krok, který je podle
      předávacího protokolu na řadě.

      Doporučení: do deploy.yml přidat před regresní krok
        npm run build:school-server
      nebo skriptu předávat kontrolované adresáře argumentem, aby
      v CI kontroloval jen to, co se tam skutečně staví. Variantu
      "chybějící staging přeskoč" nedoporučuji, oslabila by kontrolu.

      Vedlejší poznámka ke stejnému skriptu: při chybějícím adresáři
      spadne neošetřenou výjimkou ENOENT místo toho, aby vypsal svůj
      JSON report a skončil řízeně. Report se tak v CI logu vůbec
      neobjeví. Stálo by za to čtení indexu a manuálu obalit tak,
      aby skript vždy doběhl do svého souhrnu.
